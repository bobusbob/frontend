# Decisions: Веб-сервис суммаризации видео (UI/UX)

## 1. Концепция интерфейса: Single-Screen Utility (Одноэкранная утилита)

**Date:** 2026-11-25

**Decision:** Интерфейс строится как одностраничный центрированный сервис в духе продуктов Vercel, Linear и Raycast с максимальным фокусом на контенте и отсутствии визуального мусора.

**Rationale:** Сервис решает одну конкретную задачу пользователя: быстро получить суть видео. Пользователю не нужны многоуровневые меню, сложные настройки или перегруженные баннеры. Ввод данных должен быть доступен в первые 2 секунды после захода на сайт.

**Alternatives:** 
- Классический лендинг со скроллом и формами внизу страницы (отклонено: ухудшает конверсию и создает лишние шаги).
- Dashboard со сложным сайдбаром (отклонено: избыточно для минималистичной бесплатной утилиты).

---

## 2. Организация ввода: Двухрежимный переключатель (Tabs: YouTube / Файл)

**Date:** 2026-11-25

**Decision:** Использовать аккуратный segmented control (пилюльные табы) над областью ввода: переключение между «YouTube ссылка» и «Загрузка файла».

**Rationale:** Разные типы ввода требуют разного UX: для YouTube нужна строка с быстрым Paste из буфера и превью обложки, а для файла — комфортная Drag & Drop зона с индикатором прогресса загрузки. Разделение через табы сохраняет чистоту экрана и избавляет от визуального хаоса.

**Alternatives:** 
- Единое поле-«всеядный комбайн» (отклонено: технически сложнее объяснить пользователю, куда вставлять ссылку, а куда перетаскивать 300-мегабайтный файл).

---

## 3. Цветовая модель: Dark-Mode First с поддержкой Light Mode

**Date:** 2026-11-25

**Decision:** Основной фокус на глубокую темную тему (глубокий обсидиан #09090B, тонкие границы #27272A, неоновый акцент индиго/электрик-фиолет), но с поддержкой чистой светлой темы (Off-white #F8FAFC) через стандартный переключатель.

**Rationale:** Тёмная тема воспринимается современнее и премиальнее, снижает нагрузку на глаза при чтении длинных выжимок текстов и идеально сочетается со стилем Vercel.

---

## 4. Фронтенд отдельно от анализа видео

**Date:** 2026-11-25

**Decision:** Интерфейс живёт в `video-summarizer/convert Video` на Next.js (App Router), Tailwind CSS, Framer Motion и Lucide. Кнопка «Создать краткое содержание» вызывает `createSummary`. Пока функция только показывает шаги и пример карточки. Настоящий запрос к серверу подставим в эту же функцию.

**Rationale:** PRD фиксирует стек и просит сначала собрать экран. Отдельная функция не даёт размазать будущий API по компонентам. Пример явно помечен в карточке, файл и ссылка не уходят с устройства.

**Alternatives:**
- Сразу рисовать пустую карточку без текста (отклонено: не видно, как читаются тезисы, таймкоды и экспорт).
- Притворяться, что ролик уже проанализирован (отклонено: пользователь примет пример за настоящую выжимку).

---

## 5. Бэкенд YouTube: Supadata кусками, затем Gemini

**Date:** 2026-11-25

**Decision:** Для ссылки YouTube сервер запрашивает у Supadata транскрипт с `text=false` и `mode=auto`, при ответе 202 опрашивает `/transcript/{jobId}`, затем отправляет склеенный транскрипт в `gemini-4-hydrogen` через `interactions.create`. Ответ — JSON тезисов и глав. Таймкоды сверяются с `offset` кусков. Карточка уходит на экран потоком SSE.

**Rationale:** Куски с миллисекундами дают настоящие таймкоды для перехода в ролик. Сплошной текст заставил бы модель выдумывать минуты. Поток событий совпадает с тремя шагами экрана и не требует базы.

**Alternatives:**
- `text=true` (отклонено: в ответе нет таймкодов).
- Один молчаливый POST до готовой карточки (запасной вариант, если поток будет неудобен).
- Supadata Extract вместо своего промпта Gemini (отклонено: выжимку должен собирать указанный вызов Gemini).

---

## 6. Файл с компьютера: локальный faster-whisper и Word

**Date:** 2026-11-25

**Decision:** Полный текст файла распознаётся локально библиотекой faster-whisper, модель `small`, на `127.0.0.1:8765`. Сайт только показывает текст и собирает `.docx` в браузере. В Supadata и Gemini файл не отправляется.

**Rationale:** Нужна дословная расшифровка, а не выжимка, и без облачной нейросети. Vercel не примет файл до 500 МБ и не удержит долгое распознавание. Локальная программа оставляет ролик на компьютере.

**Alternatives:**
- Распознавание в браузере (отклонено для длинных файлов: не хватает памяти).
- Supadata по файлу (отклонено на этом шаге: это снова облако).

---

## 7. Публикация YouTube на Netlify отдельной папкой

**Date:** 2026-11-26

**Decision:** Сайт для Netlify лежит в `video-summarizer/netlify-site` и принимает только ссылку YouTube. Supadata и Gemini вызываются фоновой функцией `summarize-background`. Страница создаёт задачу и опрашивает `/api/jobs/[id]`. Результат пишется в Netlify Blobs. Ключи задаются в настройках сайта Netlify.

**Rationale:** Обычная функция Netlify обрывается через 60 секунд, а транскрипт и ответ Gemini вместе длятся дольше. Netlify Drop публикует только файлы и не выполняет функции, поэтому папку нельзя просто перетащить: сайт нужно собрать через Git (базовая папка `video-summarizer/netlify-site`) или `npx netlify deploy --build --prod`. Локальная расшифровка файла остаётся в `convert Video` и `transcribe`.

**Alternatives:**
- Тот же длинный поток SSE, что на локальном сервере (отклонено: Netlify оборвёт его раньше готовой карточки).
- Вызов обоих API из браузера, чтобы сработало перетаскивание папки (отклонено: ключи оказались бы в открытом коде).
